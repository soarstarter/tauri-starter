# Repository Guidelines

## Scope

- This is Tauri Starter, the open-source, fully local edition of SoarStarter's Tauri template. It needs no backend and
  the app makes no network requests at runtime.
- Do not add features that need a backend service (accounts, payments, cloud sync, telemetry, update feeds) or a release
  pipeline (signing, notarization). Those belong to the commercial edition; the Showcase only lists them through
  `src/showcase/pro-catalog.ts`.
- Keep the `csp` and `devCsp` in `src-tauri/tauri.conf.json` closed to external origins, and do not add an HTTP client
  crate to `src-tauri/Cargo.toml`.
- `pnpm check:lite` enforces these boundaries from `lite-manifest.json` (forbidden paths, words, npm and Cargo
  dependencies, Tauri config, CSP, and a gitleaks secret scan). It runs in CI and as a pre-push hook; keep it passing.

## Project Structure & Module Organization

- `src/`: Frontend (React + TypeScript). Routes, components, hooks, locales, styles, and entry files like `src/main.tsx`
  and `src/App.tsx`.
- `src/lib/tauri/`: Typed wrappers over the generated command bindings, plus the event helper and the external-URL
  guard.
- `src/lib/bindings.ts`: Generated by `tauri-specta` from the Rust commands. Never edit it by hand.
- `src/lib/settings/`, `src/lib/intents/`, `src/lib/menu/`, `src/lib/tray/`: Settings store and backup, deep links and
  argv intents, and the native menu and tray (built from TypeScript).
- `src/showcase/`: Template capability catalog, types, and the Pro catalog. Demo-only; marked with `[template-demo]`.
- `src/routes/showcase/`: Showcase pages, Components gallery, and live demos. Demo-only; safe to delete after following
  `docs/CUSTOMIZE.md`.
- `src-tauri/src/`: Rust shell. `lib.rs` registers plugins and commands; `commands/` holds the `#[tauri::command]`
  modules.
- `src-tauri/capabilities/`: Permission grants for the webview. Keep them narrow; see `docs/CAPABILITIES.md`.
- `resources/build/`: Tray icons. App icons live in `src-tauri/icons/`.
- `shared/`: Brand constants (`shared/constants.ts`) and config flags (`shared/config.ts`).
- Config lives at repo root and in `src-tauri/`: `vite.config.ts`, `eslint.config.mjs`, `.prettierrc`, `tsconfig*.json`,
  `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`.

## Build, Test, and Development Commands

- `pnpm dev`: Start the Tauri app with Vite hot reload.
- `pnpm dev:web`: Start only the Vite frontend in a browser; native APIs are unavailable there.
- `pnpm build`: Build unsigned installers for the current platform.
- `pnpm tauri build --no-bundle`: Compile a release binary without packaging, as CI does.
- `pnpm lint` / `pnpm lint:check`: Run ESLint with or without auto-fix.
- `pnpm typecheck`: Type-check the frontend.
- `pnpm format` / `pnpm format:check`: Apply or check Prettier formatting.
- `cargo fmt`, `cargo clippy`, `cargo test` with `--manifest-path src-tauri/Cargo.toml`: Format, lint, and test the Rust
  side. `cargo test` also regenerates `src/lib/bindings.ts`.

## Coding Style & Naming Conventions

- Languages: TypeScript for the frontend, Rust for the native shell.
- Formatting: Prettier (2-space indentation, single quotes, no semicolons, 120-char line width) and `rustfmt`.
- Linting: ESLint + `typescript-eslint` + React/React Hooks plugins; `clippy` with warnings denied.
- Naming patterns:
  - React components: `PascalCase` (for example `AppHeader.tsx`).
  - Hooks: `kebab-case` filename with `use-` prefix (for example `use-tauri.ts`).
  - Utility modules: descriptive `kebab-case` filenames. Rust modules: `snake_case`.
- New native calls: a `#[tauri::command]` + `#[specta::specta]` function in `src-tauri/src/commands/`, registered in
  `collect_commands![…]` in `src-tauri/src/lib.rs`, then `cargo test` to regenerate and commit `src/lib/bindings.ts`.

## Testing Guidelines

- Frontend unit tests run with Vitest via `pnpm test` (core suite) and `pnpm test:unit` (all tests, as in CI). Rust
  tests live in `#[cfg(test)]` modules and run with `cargo test`.
- Minimum quality gate for changes: run `pnpm check:lite`, `pnpm format:check`, `pnpm lint:check`, `pnpm typecheck`,
  `pnpm test:unit`, `cargo fmt --check`, `cargo clippy -- -D warnings`, and `cargo test` (the cargo commands with
  `--manifest-path src-tauri/Cargo.toml`), then confirm `git diff --exit-code -- src/lib/bindings.ts` is clean.
- For UI or native changes, manually verify in `pnpm dev` (window actions, frontend state, and command calls).
- If adding tests, prefer colocated `*.test.ts` or `*.test.tsx` near the feature.

## Template Showcase Deletion

- The template Showcase is enabled by default with `VITE_SHOWCASE_ENABLED=true`. The native menu is built in
  TypeScript and reads the same flag.
- Set it to `false` to preview the app without demo surfaces before deleting files.
- Files and core touchpoints marked `[template-demo]` are part of the removable demo layer; follow `docs/CUSTOMIZE.md`
  before deleting `src/showcase/` or `src/routes/showcase/`.

## Commit & Pull Request Guidelines

- Follow Conventional Commit style: `fix: ...`, `chore: ...`, `refactor: ...`.
- Keep commits scoped and atomic; avoid mixing refactors with behavior changes.
- PRs should include:
  - Clear summary of user-visible and technical changes.
  - Linked issue/task when applicable.
  - Validation steps run (the quality gate above, manual checks).
  - Screenshots or short recordings for UI changes.
